Summary — English Overview

MoM Biz Reg System SHV Case · May 13, 2026

🎯
Goal
To finalize the functional requirements and system interface design for the new Tax Incentive issuance process for registered enterprises (Special Investment Projects in Sihanoukville) within the GDT registration management system.
📌
Objective
Streamline the drafting and issuance of tax incentive letters by migrating to a three-level approval workflow and enhance automation for date calculation and status tracking.
💡
Key Takeaways
  • Workflow re-categorized into three levels (L1: Officer, L2: Chief, L3: Director General) to reflect hierarchical administrative structure.
  • IT department will implement auto-calculation of end dates based on the selected tax incentive term (e.g., 3-year term → auto-expiry Dec 31 of end year).
  • "Print Draft" buttons to be added at each level to facilitate document review before official submission.
  • "Remark" columns for manual entries and updated interface modifications for better data entry and cross-departmental collaboration.
📝
Detailed Summary
System Interface
Updates needed for the "Action" tab, including clearer "Agree" and "Signature" placeholders for the Director General. DAGA will finalize and submit revised letter templates to DICT.
Workflow Automation
The system will calculate and display expiration dates automatically based on selected years (e.g., 3-year term from 01.05.26 → auto-expiry 31.12.28).
Communication
Officers can print draft letters with automated annexes for verification. "Print Draft" buttons to be added at Level 1 and Level 2 approval screens.
Collaboration
DAGA will provide updated draft templates to DICT, which will prioritize immediate implementation of these system changes to align with GDT strategic plan.
⚡
Take-Action Plan
01
DAGA: Finalize and submit all revised letter templates and flow requirements to DICT.
02
DICT: Update the system interface, integrate the requested buttons, and enable the "detect end date" script.
03
Next Steps: Both teams to continue development immediately to align with the GDT strategic plan.

GDT Tax Incentive Workflow System · For Developers & Architects

1

Project Overview & Scope

🎯 System Goal
Develop a Tax Incentive Letter workflow system for Sihanoukville Special Investment Projects (SHV), integrated into GDT's existing Business Registration Management System (Biz Reg System).
🏢 Business Context
GDT (General Department of Taxation) needs to issue tax incentive letters to registered enterprises under the Sihanoukville investment scheme, with a 3-level hierarchical approval workflow.
⚙️ Core Constraint
Must integrate with existing GDT registration system, support Khmer/English bilingual output, and maintain audit trail for all approval actions.
👥 Stakeholders
DAGA (Admin): Drafts letter templates, defines workflow rules. DICT (IT): Implements system changes, integrates buttons/APIs. DG (Director General): Final approval authority.

Data Models & API Contracts

📋 Database Schema: tax_incentive_requests
CREATE TABLE tax_incentive_requests (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    enterprise_name VARCHAR(255) NOT NULL,
    tax_id          VARCHAR(50) NOT NULL,
    incentive_type_id INT NOT NULL,
    start_date      DATE NOT NULL,
    end_date        DATE GENERATED ALWAYS AS (
        CASE WHEN duration_years = 3 THEN DATE(start_date + INTERVAL 3 YEAR - 1 DAY)
             WHEN duration_years = 5 THEN DATE(start_date + INTERVAL 5 YEAR - 1 DAY)
        END
    ),
    duration_years  INT NOT NULL DEFAULT 3,
    current_level   ENUM('L1','L2','L3','APPROVED','REJECTED') DEFAULT 'L1',
    status          ENUM('DRAFT','PENDING','APPROVED','ISSUED') DEFAULT 'DRAFT',
    remarks         TEXT,
    created_by      INT,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (incentive_type_id) REFERENCES incentive_types(id),
    FOREIGN KEY (created_by) REFERENCES users(id)
);

CREATE TABLE workflow_transitions (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    request_id      INT NOT NULL,
    from_level      VARCHAR(10),
    to_level        VARCHAR(10),
    action          ENUM('SUBMIT','APPROVE','RETURN','PRINT','ISSUE') NOT NULL,
    performed_by    INT NOT NULL,
    decision_notes  TEXT,
    action_date     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (request_id) REFERENCES tax_incentive_requests(id),
    FOREIGN KEY (performed_by) REFERENCES users(id)
);
🔌 API Endpoints Reference
POST   /api/v1/incentive-requests
       → Creates new tax incentive request (Level 1 draft)
       Body: { enterprise_name, tax_id, incentive_type_id, start_date, duration_years }
       Response: { id, enterprise_name, start_date, end_date, status: "DRAFT" }

GET    /api/v1/incentive-requests
       → List all requests (filter: ?level=L1&status=PENDING)
       Response: { data: [...], pagination: {...} }

GET    /api/v1/incentive-requests/{id}
       → Get single request with full history
       Response: { request: {...}, transitions: [...], current_level: "L1" }

PATCH  /api/v1/incentive-requests/{id}/submit
       → Submit draft to L1 Officer for review
       Body: { remarks?: string }
       Response: { status: "PENDING", current_level: "L1" }

PATCH  /api/v1/incentive-requests/{id}/approve-l1
       → L1 Officer approves and forwards to L2
       Body: { remarks?: string }
       Response: { status: "PENDING", current_level: "L2" }

PATCH  /api/v1/incentive-requests/{id}/approve-l2
       → L2 Chief approves and forwards to L3
       Body: { remarks?: string }
       Response: { status: "PENDING", current_level: "L3" }

PATCH  /api/v1/incentive-requests/{id}/approve-l3
       → L3 DG final approval - issues certificate
       Body: { decision: "APPROVED", notes?: string }
       Response: { status: "APPROVED", current_level: "L3", end_date: "2028-12-31" }

GET    /api/v1/incentive-requests/{id}/calculate-end-date
       → Auto-calculates end date based on start_date + duration
       Query: ?start_date=2026-05-01&duration_years=3
       Response: { start_date: "2026-05-01", end_date: "2028-12-31" }

GET    /api/v1/incentive-requests/{id}/print-draft
       → Returns draft letter PDF for printing
       Response: PDF binary stream
⚠️ Edge Cases & Business Rules
Edge 1
Manual End Date Override: If officer selects non-standard duration, system shows alert and requires entry in Remark column explaining reason before allowing submission.
Edge 2
Return to Draft: If any level requests revision, request returns to L1 with flag "REVISION_REQUIRED". L1 officer must re-submit after corrections.
Edge 3
Concurrent Editing: If two users open same request, second user sees "Locked by [user]" warning. Must wait or force-unlock (admin only).
Edge 4
Expiry Auto-Detection: System auto-detects if current date > end_date and marks status "EXPIRED". Triggers notification to enterprise and L1 officer.
